# tdgl-simulator

Time-dependent Ginzburg–Landau simulation of vortex dynamics in constricted current-carrying superconducting channels.

## Overview

This code solves a generalized time-dependent Ginzburg–Landau (gTDGL) equation for fast-moving vortices, a current continuity equation (Poisson eq.), and Ampere's Law. The simulations are of a two-dimensional superconducting film containing a geometric constriction, under an applied perpendicular magnetic field and a transport current.

The order parameter $\psi$, scalar potential $\phi$, and vector potential **A** are evolved together on a uniform grid. Each timestep computes the gauge-covariant Laplacian of $\psi$, evaluates the supercurrent $J_s$ and its divergence, solves the resulting sparse linear system for $\phi$ with [MUMPS](https://mumps-solver.org/), then updates **A**, the normal current $J_n$, the electric field, and the dissipated power density.

The code was written to study how the critical current - the minimum transport current at which the first vortex enters the system - depends on applied field, constriction width, and the Ginzburg–Landau parameter $\kappa$. Scripts under `analysis/checks/` verify fluxoid and phase quantization to count vortices and as a verification of correctness on the solver.

## Documentation

Full derivations, dimensionless scaling, and the numerical scheme are in [docs/tdgl-documentation.pdf](docs/tdgl-documentation.pdf).

On Ubuntu 24.04:

```bash
sudo apt install -y gfortran make openmpi-bin libopenmpi-dev \
    libmumps-dev libmumps-headers-dev libscalapack-openmpi-dev \
    libopenblas-dev libmetis-dev
```

For the Python scripts:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

## Build

```bash
cd app
mpifort -fopenmp -I/usr/include tdgl.F90 -o tdgl \
    -ldmumps -lscalapack-openmpi -lopenblas
```

## Running

```bash
cd app
mkdir -p data
export OMP_NUM_THREADS=8
./tdgl
```

Change a value, build, rerun. Then plot animations of fields and diagnostics:

```bash
cd ../analysis
python diagnostic.py
```

Parameter sweeps live under `sweeps/`, each with a SLURM array-job script that partitions field values across tasks:

```bash
cd sweeps/hp_vs_kappa_vs_size
for k in 2.0 3.0 5.0 8.0; do sbatch sweep_hp_kappa_size.sh $k; done
```

## Output

The solver writes `real(8)` / `complex(8)` binary dumps into `data/`, one record every `stride` timesteps:

| File | Contents |
|---|---|
| `psi.bin` | complex order parameter $\psi$ |
| `phi.bin` | scalar potential $\phi$ |
| `Js.bin` | supercurrent density |
| `Jn.bin` | normal current density |
| `Jtot.bin` | total current density |
| `div_Js.bin` | divergence of the supercurrent |
| `div_Jtot.bin` | divergence of total current density |
| `vec_pot.bin` | vector potential **A** |
| `div_A.bin` | divergence of vector potential **A** |
| `power.bin` | dissipated power density |

Sweeps instead write plain-text tables to `data/grid_task<N>.txt` and `data/grid_k<kappa×100>_task<N>.txt`, one row per (field, current) pair with a flag for whether a vortex entered.

None of this is available to clone from the repository - a full run produces several GB. Everything in `data/` is regenerated by rerunning the solver.
