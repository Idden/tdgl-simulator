# tdgl-simulator

Time-dependent Ginzburg–Landau simulation of vortex dynamics in
current-carrying superconducting constrictions.

## Overview

This code solves the generalized time-dependent Ginzburg–Landau (gTDGL)
equations for a two-dimensional superconducting film containing a geometric
constriction, under an applied perpendicular magnetic field and a transport
current.

The order parameter ψ, scalar potential φ, and vector potential **A** are
evolved together on a uniform grid. Each timestep computes the gauge-covariant
Laplacian of ψ, evaluates the supercurrent **J**ₛ and its divergence, solves
the resulting sparse linear system for φ with
[MUMPS](https://mumps-solver.org/), then updates **A**, the normal current
**J**ₙ, the electric field, and the local dissipated power.

The code was written to study how the critical current - the transport current
at which the first vortex enters the constriction - depends on applied field,
constriction width, and the Ginzburg–Landau parameter κ. Scripts under
`analysis/checks/` verify flux and phase quantization as a correctness test on
the solver.

## Requirements

| Component | Version |
|---|---|
| gfortran | 13.3.0 |
| OpenMPI | 4.1.6 |
| MUMPS | 5.6.2 |
| ScaLAPACK | 2.2.1 |
| OpenBLAS | 0.3.26 |
| METIS | 5.1.0 |
| Python | 3.12 |

On Ubuntu 24.04:

```bash
sudo apt install -y gfortran make openmpi-bin libopenmpi-dev \
    libmumps-dev libmumps-headers-dev libscalapack-openmpi-dev \
    libopenblas-dev libmetis-dev
```

For the Python analysis scripts:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

## Build

```bash
cd app
mpifort -fopenmp -O2 -I/usr/include gTDGL.F90 -o gTDGL \
    -ldmumps -lscalapack-openmpi -lopenblas
```

The capital `.F90` extension triggers the C preprocessor, which the OpenMP
guards require.

## Running

```bash
cd app
mkdir -p data
export OMP_NUM_THREADS=8
./gTDGL
```

Simulation parameters are compile-time constants near the top of `gTDGL.F90`:

| Parameter | Meaning | Default |
|---|---|---|
| `dimx`, `dimy` | grid dimensions | 60 × 60 |
| `ymax` | domain height | 30 |
| `n_t` | number of timesteps | 100000 |
| `tmax` | total simulated time | 1000 |
| `n_relax` | relaxation steps before ramping | 5000 |
| `n_ramp` | steps over which the field is ramped | 5000 |
| `kappa` | Ginzburg–Landau parameter | 2.1 |
| `sigma_n` | normal-state conductivity | 1.0 |
| `H_ext` | applied perpendicular field | 0.0353 |
| `current_max` | peak transport current | 0.15 |
| `stride` | timesteps between field dumps | 250 |

Change a value, recompile, rerun. Then plot:

```bash
cd ../analysis
python gTDGL_plotting.py
```

Parameter sweeps live under `sweeps/`, each with a SLURM array-job script that
partitions field values across tasks:

```bash
cd sweeps/kappa
sbatch gTDGL_sweep_kappa.sh 3.0
```

## Output

The solver writes `real(8)` / `complex(8)` binary dumps into `data/`, one
record every `stride` timesteps:

| File | Contents |
|---|---|
| `psi.bin` | complex order parameter ψ |
| `phi.bin` | scalar potential φ |
| `Js.bin` | supercurrent density |
| `Jn.bin` | normal current density |
| `Jtot.bin` | total current density |
| `div_Js.bin` | divergence of the supercurrent |
| `vec_pot.bin` | vector potential **A** |
| `power.bin` | local dissipated power |

Sweeps instead write plain-text tables to `data/grid_task<N>.txt`, one row per
(field, current) pair with a flag for whether a vortex entered.

None of this is in the repository - a full run produces several GB. Everything
in `data/` is regenerated by rerunning the solver.
